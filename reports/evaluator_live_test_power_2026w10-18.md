## 1. Method

**Pool.** The validated walk-forward run `default_20261102` (predictions sha256 `58d782bfb3336b56...`, calibration `v3-tie-aware-quantile`), PPR, seasons 2022-2024, as in `reports/backtest_2026-11-03_v3.md`. The focus is `chain_v1+cal`, the chain with the walk-forward (online) calibrator, which is the chain_v2 calibration method (D-098 item 2b). The comparators are the calibrated forms of `rolling_avg_4`, `prior_season` and `rolling_median_8`; the start/sit comparator is the FantasyPros consensus on the D-077 common pair set. Populations, the pair set and the randomized PIT come from the real report functions (`headline_frames`, `consensus_population`, `with_randomized_pit`, `bounds_from_run`).

**One replicate.**

1. For each week number w of the window, one slate is drawn uniformly from 2022, 2023 and 2024 week w. Whole slates keep the correlation within a week and within a game.
2. If the slate has more games than 2026 week w (14, 13, 16, 14, 15, 16, 16, 16, 16 for weeks 10-18), whole games are dropped uniformly at random until the counts match: every row of both teams goes, both DST rows go, and the start/sit pair set is re-ranked on the remaining players, so pairs involving dropped players go and players below the cut on the full slate can enter it. Slates with fewer games are kept (frequency in section 3.5).
3. The window is relabelled season 2026 (one bootstrap cluster per week, the live sort order) and the 22 lines are evaluated as `ffml/eval/report_holdout.py` does: 500 week-clustered paired bootstrap draws, seed 0, percentile 95% interval (D-078); L01-L12 pass when all four intervals (MAE, pinball q10, q50, q90) of chain minus comparator lie entirely below 0; L13-L16 pass unless the start/sit interval of chain minus consensus lies entirely below 0; L17-L22 pass when tie-aware coverage (randomized PIT in (0.1, 0.9)) lies in [0.75, 0.85] (D-085).

**Scenarios.**

- `A`: A: well calibrated (rank-calibrated PIT), accuracy as validated.
- `B`: B: as validated (chain_v1+cal unchanged, PIT redrawn with seed 0).
- `C_shift_0.75`: C: A with the chain's mean edge on L01-L12 shrunk to 0.75x (noise kept).
- `C_shift_0.5`: C: A with the chain's mean edge on L01-L12 shrunk to 0.5x (noise kept).
- `C_scale_0.75`: C literal: A with per-row differences scaled by 0.75.
- `C_scale_0.5`: C literal: A with per-row differences scaled by 0.5.
- `B_fixed`: B sensitivity: validation PIT draws kept (not redrawn).
- `A_vc`: A sensitivity: variance-corrected slate draws (x sqrt(3/2)).
- `A_w`: A calibrated on the test weeks: ranks over the 2022-2024 rows of weeks 10-18 only.

Details. A: within each position each row's validation PIT u (seed 0, the v3 draws) is replaced by its rank score u' = (rank - 0.5)/n over all 2022-2024 rows of the position, so pooled coverage is 0.800 at every position (to within 1/n) and the dependence between rows (same week, same game) is kept. B: rows unchanged; the PIT is redrawn on the window exactly as the live test will draw it (one seed-0 generator over the window's rows in season, week, position, entity order). B_fixed keeps the validation draws instead. C (shift): every per-row chain-minus-comparator loss difference behind L01-L12 is moved by (1 - k) times its 2022-2024 mean at that position, so the expected edge is k times the validated edge and the week-to-week noise is unchanged; start/sit and coverage as in A. C (scale, the literal brief): every per-row difference multiplied by k. A_w: as A, but the ranks are taken over the 2022-2024 rows of weeks 10-18 only, so coverage is 0.80 over the test weeks rather than over the whole season (in window (ii) and (iii) weeks outside 10-18 keep A's scores). A_vc: as A, but each simulated week's sums are moved away from the mean of their week number by the factor sqrt(3/2) (section 4, item 1).

**Windows.** (i) weeks 10-18 with the 2026 game counts; (ii) weeks 11-18 with the 2026 game counts; (iii) weeks 1-18 with full slates, for reference.

**Seeds.** Bootstrap seed 0 with 500 draws and metric seed 0 (the pre-registered values); slate and game draws seed 20261104.

## 2. The fast path reproduces the real code

Every statistic behind the 22 lines is a ratio of sums: over rows for MAE, pinball and coverage, over pairs for start/sit. The bootstrap resamples whole weeks, so a draw is (C @ sums) / (C @ counts), where C[b, j] counts how often draw b picks week j. C is built from the same generator calls as `metrics._paired_bundle_bootstrap` (`default_rng(0).integers(0, K, (500, K))`). Per game the fast path keeps loss sums and counts per model and metric, coverage counts and PIT limits F(y-), F(y); per slate-position it keeps the consensus-population rows in D-077 reference order with each model's pair concordances. A thinned slate's pair set is "the first N kept rows in reference order", which is what `with_reference_rank` gives on the thinned frame.

## 4. Assumptions and approximations

1. **Three slates per week number.** Each simulated week is one of only three real slates. The spread of a uniform pick among three values is the plug-in variance, which is 2/3 of the true slate-to-slate variance in expectation, so window-level noise is understated. `A_vc` stretches each simulated week's deviation from its week-number mean by sqrt(3/2) to undo this in expectation; compare A and A_vc for the size of the effect.
2. **Season-level shifts are not simulated.** Weeks are drawn independently across 2022-2024, so a shift shared by every week of 2026 (as in 2025, when QB coverage of the frozen chain fell from 0.779 in validation to 0.739) is not represented; section 3.4 shows the coverage lines' pass probability as a function of the true coverage level instead.
3. **chain_v1+cal stands in for chain_v2.** chain_v2 adds 2025 to training and uses the walk-forward calibrator; chain_v1+cal is that calibrator on chain_v1 (D-098 item 2b). The live test's calibrator starts from 2025 weeks rather than 2021, which is not simulated.
4. **Scenario A keeps the validation PIT draws.** u' is a fixed function of each row's seed-0 validation PIT, as the brief defines it; it is not redrawn per window. Scenario B redraws exactly as the live test will; B_fixed shows that the redraw changes little.
5. **The pair set.** The D-077 reference is the mean raw pred_q50 of the models in the validation run's primary configuration (chain_v1, direct_lgbm, the five baselines) plus the consensus. If the live test compares a different model set, its pair set differs slightly. Thinning re-ranks the pair set on the kept players, exactly as the real code would on a 2026 slate with fewer games.
6. **Consensus availability.** The consensus population lacks players whose game precedes the Friday scrape (Thursday games), as it will in 2026, and the archive has no week 18 scrape in 2022-2024; the simulation keeps both. If 2026 week 18 has a consensus scrape, the start/sit lines get one more week.
7. **Game counts.** Slates with fewer games than 2026 are kept, so window (i) has slightly fewer games on average than the 136 scheduled (section 3.5); dropped games are chosen uniformly (not by kickoff slot).
8. **PIT bounds.** The run's own prior-season position bounds (`pos_min` / `pos_max`, identical in 2022-2024) are used, as `report_holdout` does; they reproduce the v3 coverages exactly.
9. **Literal C is invariant.** Multiplying every per-row difference by k > 0 multiplies the point delta and every bootstrap difference by k, so an interval entirely below 0 stays entirely below 0. The shift form is reported as the operative accuracy sensitivity; both are shown.
10. **Data read.** Only 2022-2024 PPR rows of `default_20261102` and the consensus for 2022-2024 (`consensus_predictions(purpose='backtest')`, which, as in the v3 report, fits its rank-to-points curve on earlier archive seasons up to 2024). Nothing from 2025, 2026, `data/backtests/holdout_2025` or `data/backtests/forward_2026` was read.
